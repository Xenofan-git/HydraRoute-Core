# HydraRoute Core L7 sniffing — Debian adaptation — 2026-11-09

## Original HRNeo behavior

HRNeo 3.24.2-1 exposes these controls:
- `l7CaptureEnabled` (default false)
- `l7EnableTLS` (default true)
- `l7EnableHTTP` (default true)
- `l7EnableQUIC` (default true)
- `l7NflogGroup`, `l7WanInterface`, `l7ConnbytesMax`
- TCP/QUIC reassembly controls and conntrack-flush behavior.

When enabled, original HRNeo captures copies of forwarded LAN/VPN client packets through NFLOG/iptables, parses TLS ClientHello SNI, HTTP Host and QUIC Initial SNI, then adds matched destination IPs to the relevant ipset. It also depends on Linux kernel netfilter modules and has careful conntrack handling.

## Debian safety boundary and chosen adaptation

The Core implementation deliberately does **not** reproduce HRNeo's host-wide packet capture:
- no NFLOG socket;
- no iptables/ip6tables/nftables rules;
- no kernel module loading;
- no conntrack flush/delete;
- no system routing changes;
- no visibility into unrelated LAN/VPN transit traffic or traffic generated by other local processes.

Instead, it enables Xray's native inbound sniffing only on HydraRoute Core's own SOCKS5 inbounds. This is an intentional, narrower adaptation.

## Implemented behavior

New persistent settings:
- `enabled` — default false;
- `http` — default true;
- `tls` — default true;
- `quic` — default true.

API:
- `GET /v1/l7/settings` — local-read only.
- `PUT /v1/l7/settings` — local same-origin JSON only.
- State file: `<stateDir>/l7/settings.json`, private directory mode 0700 and file mode 0600.
- When enabled, at least one protocol must be selected.
- Settings apply on the next Xray configuration build; saving them does not restart the current process.

Compiler:
- Applies `sniffing.enabled=true` only to Core profile SOCKS5 inbounds and the optional shared SOCKS5 inbound.
- `destOverride` is assembled in stable order from selected `http`, `tls`, `quic` protocols.
- Uses `metadataOnly=false` and `routeOnly=true`, so the sniffed host can be used for routing without replacing the original destination used for the connection.
- Does not add sniffing to the private Observatory `dokodemo-door` API inbound.
- Disabled by default, matching HRNeo's `l7CaptureEnabled=false` default.

UI:
- Settings page includes an L7 analysis card with master enable and HTTP/TLS/QUIC toggles.
- The card clearly states that the feature sees only traffic explicitly sent through Core SOCKS5 and does not use NFLOG or modify the firewall.

## Xray compatibility evidence

The installed NanoPi Xray 26.10.31 ARM64 accepted this inbound sniffing configuration in `xray run -test -config`:
- SOCKS inbound;
- `destOverride: [http, tls, quic]`;
- `metadataOnly: false`;
- `routeOnly: true`.

The config test returned `Configuration OK`. In addition, a complete config generated by the current `compiler.Compile` path (one profile SOCKS inbound, one shared SOCKS inbound, the private Observatory API inbound, and all three sniffers) was transferred to NanoPi and passed the actual ARM64 Xray `run -test`. Both tests used temporary files in `/tmp`; no listener was started and no service/configuration was changed.

## Functional end-to-end validation

Added reusable loopback-only tests: `tests/integration/l7_proxy_sniffing.py` (stdlib-only HTTP/TLS) and `tests/integration/l7_quic_sni.py` (aioquic 1.7.2; pinned in `tests/integration/requirements-quic.txt`). They start a temporary Xray process and local targets, then send SOCKS5 connections addressed to IPs while varying HTTP Host, TLS SNI or QUIC SNI. The routing rule blocks `blocked.example` and leaves `allowed.example` on the direct outbound.

Results:
- VPS Xray 26.10.31 AMD64: `L7_PROXY_SNIFFING_E2E_OK`.
- Actual NanoPi Xray 26.10.31 ARM64: `L7_PROXY_SNIFFING_E2E_OK`.
- Both HTTP Host and TLS SNI were verified end-to-end: blocked host did not reach the target; allowed host did.
- QUIC sniffing configuration is accepted by Xray config validation, but a real QUIC Initial/SNI traffic test remains pending.

The test binds only 127.0.0.1 on ephemeral ports and terminates its temporary Xray process. It does not touch the installed service, firewall, routes, DNS or system services.

## Regression coverage

- Compiler tests verify sniffing is applied to profile and shared Core SOCKS inbounds only, not the private API inbound.
- Compiler tests verify protocol selection order and reject enabled-with-empty-selection.
- API tests verify persistence, 0600 file mode, reload after server construction, applying saved settings to the next compiled Xray config, and rejection of empty enabled selection.
- Browser test verifies the L7 UI toggles persist through the API.
- VPS full Go tests, `go vet` and `git diff --check` passed. Browser/architecture CI is pending for the latest L7 commit.

## Functional limitation

This is not full HRNeo NFLOG parity. It can inspect HTTP/TLS/QUIC metadata only when the client uses a Core SOCKS5 inbound. It does not capture direct LAN/VPN traffic, local process OUTPUT traffic, DoH/DoT/DoQ contents, or ECH-protected inner names. QUIC packet parsing has been verified with aioquic on VPS Xray 26.10.31 AMD64; repeat the packet-level test on NanoPi ARM64 when the temporary aioquic test dependency can be supplied without installing system packages. It does not MITM TLS. Xray's own sniffing/reassembly implementation replaces HRNeo's custom NFLOG/TCP/QUIC packet reassembly only within the proxy ingress boundary.
